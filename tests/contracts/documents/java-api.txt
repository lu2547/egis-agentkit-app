Java 端接口文档（egis-ai-kb-service-app）
依据 egis-ai-kb-service-app 实际 Controller / DTO 源码整理，包含每个接口的路径、方法、入参、出参、字段说明与调用示例。与前端演示原型对应的接口清单见 docs/api.md；Java/Python 职责划分见 docs/java-side.md。
1. 通用约定
1.1 基础地址
项 | 说明
服务名 | kb-service-app（Spring Boot）
本地/直连 | http://{host}:{port}/knowledge（server.servlet.context-path=/knowledge）
前端/网关 | 同源 /knowledge 前缀，如 https://{gateway}/knowledge/kb
文档内变量 | BASE_URL 表示上表基础地址（含可选网关前缀）
1.2 认证
普通业务接口使用 JWT Cookie 认证，由 JwtAuthInterceptor 校验：
项 | 说明
Cookie 名 | kb_auth_token（jwtProperties.cookieName 默认值，可由 Nacos 覆盖）
兜底 SSO | JWT 无效/缺失时尝试 CAS_SSO_COOKIE（CAS 单点登录自动换取 JWT）
免认证路径 | /auth/authenticate、/auth/public-keys、/v1/health、/openapi/**、/error
失败响应 | HTTP 401，响应体 {"code":1001,"message":"未登录或登录已过期","data":null,"success":false}
备注 | /openapi/** 使用独立 HMAC-SHA256 签名认证，见第 11 节。
1.3 统一响应壳
{"code":0,"message":"OK","data":{}}
字段 | 类型 | 说明
code | int | 0 成功，非 0 为错误码
message | String | 结果描述
data | T | 业务数据，无返回时为 null
success | boolean | 序列化时由 isSuccess() 派生，code==0 时为 true
1.4 分页结构
{"total":100,"items":[]}
字段 | 类型 | 说明
total | long | 总记录数
items | T[] | 当前页数据
分页参数命名不统一：/kb、/wiki、/v1/reviews 用 page + pageSize/size；/v1/tasks 用 limit + offset。
1.5 错误码
code | 枚举 | 说明
0 | SUCCESS | 成功
1000 | BAD_REQUEST | 请求参数错误
1001 | UNAUTHORIZED | 未授权 / 未登录
1002 | FILE_UNREADABLE | 文件不可读
1003 | PARSE_FAILED | 文档解析失败
1004 | NOT_FOUND | 资源不存在
1005 | CONFLICT | 资源冲突
1006 | FORBIDDEN | 无权限访问该资源
5000 | INTERNAL_ERROR | 服务内部错误
1.6 数据格式约定
时间字段为 LocalDateTime，JSON 默认格式 yyyy-MM-dd'T'HH:mm:ss（如 2026-10-31T12:00:00）。字段命名默认驼峰（camelCase），仅个别接口入参使用下划线（Controller 显式写明的 tag_id、restore_placeholder 查询参数等）。文件大小、版本号等在部分 VO 中为已格式化的展示字符串（如 size="1.2 MB"、version="v1"），DocDetailVO 同时提供原始字节数。
2. 认证接口
基路径：/auth（AuthController）
2.1 获取 SM2 公钥
GET /auth/public-keys
无需登录。前端用该公钥对登录密码做 SM2 加密。
响应 data（PublicKeyResponse）
字段 | 类型 | 说明
pubX | String | 公钥 X 分量
pubY | String | 公钥 Y 分量
curl -s "$BASE_URL/auth/public-keys"
{"code":0,"message":"OK","data":{"pubX":"...","pubY":"..."}}
2.2 账号密码登录
POST /auth/authenticate    Content-Type: application/json
无需登录。成功后服务端下发 JWT Cookie（kb_auth_token），可能同时设置 CAS_SSO_COOKIE。
请求体（LoginRequest）
字段 | 类型 | 必填 | 说明
userId | String | 是 | 用户 ID
password | String | 是 | 前端 SM2 加密后的密码
validCode | String | 否 | 验证码
loginType | String | 否 | 登录类型
响应 data（LoginResponse）
字段 | 类型 | 说明
userId | String | 用户 ID
userName | String | 用户名称
curl -s -c cookie.txt -X POST "$BASE_URL/auth/authenticate" \  -H "Content-Type: application/json" \  -d '{"userId":"u1001","password":"<SM2密文>","validCode":"","loginType":"PWD"}'
2.3 当前用户信息
GET /auth/me
响应 data（MeResponse）
字段 | 类型 | 说明
userId | String | 用户 ID
userName | String | 用户名称
groups | GroupInfo[] | 用户所属资源组列表
GroupInfo
字段 | 类型 | 说明
name | String | 组展示名称
value | String | 组编码/权限标识
curl -s -b cookie.txt "$BASE_URL/auth/me"
2.4 登出
POST /auth/logout
清除 JWT / SSO Cookie，data 为 null。
2.5 模糊查询用户
GET /auth/users?userName={keyword}&userId={keyword}
查询参数 | 类型 | 必填 | 说明
userName | String | 否 | 用户名模糊匹配
userId | String | 否 | 用户 ID 模糊匹配
响应 data（UserSearchVO[]）
字段 | 类型 | 说明
userId | String | 用户 ID
userName | String | 用户名
userCode | String | 用户工号/编码
userDesc | String | 用户描述
curl -s -b cookie.txt "$BASE_URL/auth/users?userName=张"
2.6 资源组树
GET /auth/treeGroup?filter={true|false}
查询参数 | 类型 | 默认 | 说明
filter | String | false | true 时仅保留 view/edit/manager 节点
响应 data（LabelGroupTree[]）
字段 | 类型 | 说明
label | String | 展示名称
value | String | 组编码
children | LabelGroupTree[] | 子节点
3. 知识库接口
基路径：/kb（KbController）

GET /kb?scope={all|personal|enterprise|public}&keyword={kw}&page={n}&pageSize={n}
查询参数 | 类型 | 默认 | 说明

keyword | String | — | 名称模糊搜索
page | int | 1 | 页码
pageSize | int | 20 | 每页条数
响应 data：PageResult<KbCardVO>
KbCardVO（继承 CardBaseVO）
字段 | 类型 | 说明

desc | String | 描述
owner | String | 属主 ID

pinned | Boolean | 是否置顶
lastUpdate | LocalDateTime | 最后更新时间
count | String | 文档数量（字符串）
chunkingConfig | String | 分片配置 JSON 字符串
parserConfig | String | 解析器配置 JSON 字符串
curl -s -b cookie.txt "$BASE_URL/kb?scope=all&keyword=年金&page=1&pageSize=20"
{  "code":0,"message":"OK",  "data":{    "total":1,    "items":[{      "id":"kb_001","type":"enterprise","title":"年金业务部",      "desc":"年金政策与基础知识","owner":"u1001","ownerName":"张三",      "pinned":true,"lastUpdate":"2026-10-31T10:00:00",      "count":"128","chunkingConfig":"{\"strategy\":\"hierarchical\"}","parserConfig":"{}"    }]  }}

请求体（KbCreateRequest，继承 KbBaseRequest）

chunkingConfig | String | 否 | 分片配置 JSON 字符串
parserConfig | String | 否 | 解析器配置 JSON 字符串

响应 data
字段 | 类型 | 说明
id | String | 新建知识库 ID

3.3 知识库详情
GET /kb/{kb_id}
响应 data：KbCardVO（字段同 3.1）
curl -s -b cookie.txt "$BASE_URL/kb/kb_001"
3.4 更新知识库
PUT /kb/{kb_id}    Content-Type: application/json
请求体（KbUpdateRequest，继承 KbBaseRequest）：字段同 3.2 的 name / description / chunkingConfig / parserConfig。更新后 config_version 自动 +1。data 为 null。
curl -s -b cookie.txt -X PUT "$BASE_URL/kb/kb_001" \  -H "Content-Type: application/json" \  -d '{"name":"年金业务部（新）","description":"更新描述"}'
3.5 删除知识库
DELETE /kb/{kb_id}
逻辑删除，data 为 null。
curl -s -b cookie.txt -X DELETE "$BASE_URL/kb/kb_001"
3.6 置顶/取消置顶
POST /kb/{kb_id}/pin    Content-Type: application/json
请求体：{"pinned": true}（缺失默认 true）
字段 | 类型 | 必填 | 说明
pinned | Boolean | 否 | true 置顶，false 取消
curl -s -b cookie.txt -X POST "$BASE_URL/kb/kb_001/pin" \  -H "Content-Type: application/json" -d '{"pinned":true}'
3.7 查询知识分类标签树

curl -s -b cookie.txt "$BASE_URL/kb/kb_001/tags"

GET /kb/{kb_id}/tag/owners
响应 data：String[]，知识库关联标签的去重属主 ID 列表（前端菜单权限判断用）。
3.9 新增知识分类标签
POST /kb/{kb_id}/tags    Content-Type: application/json
请求体（TagCreateRequest）
字段 | 类型 | 必填 | 说明
name | String | 是 | 标签名称
owner | String | 否 | 标签属主 ID

3.10 修改知识分类标签

请求体（TagUpdateRequest）

响应 data：TagTreeNode
3.11 删除知识分类标签
DELETE /kb/{kb_id}/tags/{tag_id}
级联删除下级标签，data 为 null。
3.12 查询解析引擎列表（代理 Python）
GET /kb/parser-engines?fileType={type}
查询参数 | 类型 | 必填 | 说明
fileType | String | 否 | 按文件类型筛选支持该类型的引擎
响应 data：Python 侧 /v1/parsers 解开放一壳后的引擎列表与降级链（通常为 {engines:[...], chains:[...]}）。

3.13 查询知识库引擎降级链
GET /kb/{kb_id}/engines
响应 data（EngineChainVO[]）
字段 | 类型 | 说明
type | String | 文件类型（pdf/docx/txt…）
exts | String[] | 该类型支持的扩展名
chain | String[] | 引擎降级链，按优先级排列
desc | String | 引擎链说明
3.14 保存知识库引擎降级链
PUT /kb/{kb_id}/engines    Content-Type: application/json
请求体：EngineChainVO[]（字段同 3.13），data 为 null。
curl -s -b cookie.txt -X PUT "$BASE_URL/kb/kb_001/engines" \  -H "Content-Type: application/json" \  -d '[{"type":"pdf","exts":["pdf"],"chain":["mineru","vision","pandoc"],"desc":"PDF 解析链"}]'

5. 上传接口
基路径：/kb/{kb_id}/documents（UploadController）
5.1 批量上传文档
POST /kb/{kb_id}/documents/upload    Content-Type: multipart/form-data
表单参数
参数 | 类型 | 必填 | 说明
files | MultipartFile[] | 是 | 上传文件，单次最多 20 个，单个最大 50MB
fileType | String | 否 | 内容类型：text/table/image/ppt
chunkStrategy | String | 否 | 分片策略：sentence/semantic/sentence_window/hierarchical/structured，默认 hierarchical
parentSize | Integer | 否 | 父分段大小（256~8192，默认 4096）
childSize | Integer | 否 | 子分段大小（128~4096，默认 384）
overlap | Integer | 否 | 分片重叠（0~childSize-1，默认 50）
chunkParams | String | 否 | 策略专属参数 JSON 字符串
category | String | 否 | 知识分类路径
tagId | String | 否 | 知识分类标签 ID
engine | String | 否 | 首选解析引擎（空为自动选择）
validity | String | 否 | 有效期截止日期
chunkSwitch | Boolean | 否 | 是否启用切片，默认启用
响应 data
字段 | 类型 | 说明
document_ids | String[] | 新建文档 ID 列表（下划线字段）
curl -s -b cookie.txt -X POST "$BASE_URL/kb/kb_001/documents/upload" \  -F "files=@年金政策.pdf" -F "files=@说明.docx" \  -F "fileType=text" -F "chunkStrategy=hierarchical" \  -F "childSize=384" -F "overlap=50" -F "tagId=tag_001" \  -F "engine=mineru" -F "validity=2027-12-31"
5.2 替换文档原始文件
POST /kb/{kb_id}/documents/{doc_id}/replace    Content-Type: multipart/form-data
表单参数：file（必填）+ UploadFormRequest 字段（同 5.1，不含 files）。

11. OpenAPI 接口
基路径：/openapi/v1（OpenApiController）
11.1 签名认证
/openapi/** 不经 JWT 拦截器，由 OpenApiAuthFilter 做 HMAC-SHA256 签名校验。
请求头
Header | 说明
X-App-Id | 集成应用 ID（对应 llm_integration_app.app_id）
X-Timestamp | Unix 时间戳（秒），服务端校验时效窗口
X-Nonce | 随机串，防重放
X-Signature | 签名（Hex 小写）
X-Request-Id | 请求追踪 ID（可选）
待签名串（canonical string），各段以 \n 连接：
METHOD\nPATH\nCANONICAL_QUERY\nX-Timestamp\nX-Nonce\nSHA256(body)
PATH：不含 query 的请求路径（如 /openapi/v1/kb）。CANONICAL_QUERY：query 参数按 key 升序，k=v 以 & 连接；无 query 时为空串。SHA256(body)：请求体 SHA-256 的十六进制小写；无 body 时为空的 SHA-256。X-Signature = HMAC-SHA256(secret, canonicalString) 十六进制小写。
签名示例（bash + openssl）
APP_ID=app_demoSECRET=******TS=$(date +%s)NONCE=$(openssl rand -hex 8)METHOD=GETPATH_=/openapi/v1/kbQUERY=""BODY_HASH=$(printf "" | openssl dgst -sha256 -hex | awk '{print $2}')CANONICAL=$(printf '%s\n%s\n%s\n%s\n%s\n%s' "$METHOD" "$PATH_" "$QUERY" "$TS" "$NONCE" "$BODY_HASH")SIG=$(printf '%s' "$CANONICAL" | openssl dgst -sha256 -hmac "$SECRET" -hex | awk '{print $2}')

GET /openapi/v1/kb

curl -s "$BASE_URL/openapi/v1/kb" -H "X-App-Id: ..." -H "X-Timestamp: ..." -H "X-Nonce: ..." -H "X-Signature: ..."
11.3 分页查询知识库文档
GET /openapi/v1/kb/{kbId}/documents?page={n}&pageSize={n}
scope：doc.read。知识库不存在返回 1004。
响应 data：PageResult<Map>，每项字段：id、kbId、tagId、title、fileType、fileSize、parseStatus、reviewStatus、indexStatus、createdAt。
curl -s "$BASE_URL/openapi/v1/kb/kb_001/documents?page=1&pageSize=20" \  -H "X-App-Id: ..." -H "X-Timestamp: ..." -H "X-Nonce: ..." -H "X-Signature: ..."

11.6 派发任务
POST /openapi/v1/tasks/dispatch    Content-Type: application/json
scope：task.dispatch。
请求体
字段 | 类型 | 必填 | 说明
taskType | String | 是 | 任务类型
kbId | String | 是 | 知识库 ID（为空返回 1000）
docId | String | 否 | 文档 ID
响应 data：{"kbId": "kb_001", "accepted": true}
curl -s -X POST "$BASE_URL/openapi/v1/tasks/dispatch" \  -H "X-App-Id: ..." -H "X-Timestamp: ..." -H "X-Nonce: ..." -H "X-Signature: ..." \  -H "Content-Type: application/json" \  -d '{"taskType":"REINDEX","kbId":"kb_001","docId":"doc_001"}'
12. 权限模型说明
12.1 知识库角色
KbRole 层级（高 → 低）：ADMIN > OWNER > EDITOR > VIEWER > NONE。
操作 | 最低角色
查看知识库/文档/检索 | VIEWER
上传文档、提交审核、替换文件 | EDITOR（替换用 DOC_UPDATE）
审核通过/驳回、重新解析、编辑元数据、删除、置顶、标签管理 | OWNER / ADMIN / 系统管理员
文档权限通过 llm_document.tag_id → llm_kb_tag.owner_id 关联到标签属主。审核接口返回的 canAudit 表示当前用户对该审核项是否具备审核权限，前端应据此禁用"通过/驳回"按钮。OpenAPI 通过 llm_integration_app 的 scope 控制访问，与登录用户权限相互独立。
12.2 常见错误响应
{"code": 1001, "message": "未登录或登录已过期", "data": null, "success": false}
{"code": 1006, "message": "无权限访问该资源", "data": null, "success": false}

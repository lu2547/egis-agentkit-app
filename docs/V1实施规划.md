## 1. 已确定的首版范围

- 不修改 AgentScope service 源码，不复制 ChatService、AgentLoop、团队执行、消息/状态保存或 SSE。
- 配置管理统一使用已安装的 Nacos；运行参数、模型默认与规则由 framework.config 的集中 Adapter 提供。部署环境只提供 Nacos 连接引导；具体用户、Definition、USE、审核结果仍写 PG，见 [配置管理](../../egis-agentkit-framework/docs/配置管理.md)。
- 用户 user_id 为公司 um_id，姓名不唯一；User 保存 group_ids、role_type=user/admin。admin 管所有资源、用户、组、授权和共享审核；不设组管理员/发布者角色。
- 本人轻量专家/团/Skill 无审核保存自用；仅共享需 admin 审核，默认全量共享。当前共享快照不跟着私有编辑自动变。
- 系统代码资源注册后默认无 USE，admin 在授权管理页配置；管理员身份不自动获得运行时 USE。
- 个人助理默认可用，使用管理员预配规则。expert 可独立或作为成员，不能主理；orchestrator 只能团内执行。V1 固定成员，不做动态组团/增员。
- Definition 当前配置与 bindings 一起存，不存草稿、不做历史回退。共享审批快照属于当前对外视图，不是回退功能。
- 独立代码包新增/升级热加载、不重启 App；Skill/Tool 按需取得，Middleware 在 Agent 构造前取得。
- Workspace 先 local，common 只读共享资源、user 私有工作区，work 与 artifacts 分开。
- Skill 用 is_skill_market_visible 决定广场展示；Agent 归属不决定展示，展示也不授权。
- 用户后续已授权 Kafka 改造：EgisMessageBus 的 cluster 模式采用 Kafka 唤醒/广播与 PG 状态/租约；standalone 委托原生 InMemoryMessageBus。不新增 Redis，群组授权从 PG 规则读取。

## 2. 工程职责

| 工程 | 负责 |
| --- | --- |
| egis-agentkit-framework | UserService/AgentService/TeamService、共享/权限用例、增量模型和 PG 窄扩展、发布物/Loader、原生策略/Workspace/工厂/middleware 接入 |
| egis-agentkit-app | 原生 create_app 主应用与 lifespan、可信身份、薄 Controller/HTTP Schema、可选 manager_router、原生接口开放/校验 |
| egis-agentkit-frontend | Vue3 + TDesign 独立工作台，资源/任务/自用配置/共享申请，以及 admin 管理页面 |
| demo/agentscope-demo/agentkit_demo | 业务项目引入 framework，使用原生工具/middleware/Skill/MCP，构建独立发布目录并由 App 加载 |

framework 不放 HTTP DTO、不另设 Repository/Runtime；原生有能力直接复用。原生没有企业用户/审批/完整资源包等事实才增量实现。

framework 的 config 模块负责 Nacos SDK 适配、配置校验/订阅/快照；app 提供连接引导并管理客户端生命周期。用户角色赋予、资源 USE 和共享审核等管理结果不重复写入 Nacos。

## 3. PG 与原生状态

使用现有 Docker PostgreSQL（已知 agentscope-pg 宿主机 5433），数据库名和凭证从配置取，不重建/清空原库。

| 增量表 | 内容 |
| --- | --- |
| ak_users | um_id、姓名、Group、user/admin |
| ak_groups | 组基本信息；成员关系只在 User.group_ids 存一次 |
| ak_definitions | 当前配置与绑定 |
| ak_resource_assets | 完整包 URI/hash/入口/资源元数据 |
| ak_resource_grants | user/group/all_users 的显式 USE 和来源 |
| ak_share_reviews | 只审核共享，完整快照与当前共享版本 |

不另建会话、消息、技能正文或 turn/state 表。原生 agents/sessions/teams/messages/skills/mcps/credentials 继续用；SessionBinding/执行快照走原生 State.middle_context。

本地 AgentScope 树已到 v2.0.11 且存在用户既有修改，核对基线是 v2.0.10；新包不能依赖修改原生源码才能运行。原生 SkillRecord 已有 version/enabled，不重造。

## 4. App 接入与接口分工

原生 create_app 返回的 App 直接作为主应用，管理 Router 加在其上；不简单 mount 原生 App 丢失 lifespan。外部 /api 前缀由代理/网关统一处理。下列是拟定管理接口，实际与 OpenAPI 一起评审：

| 入口 | 规则/复用 |
| --- | --- |
| /manager/me | 当前用户/Group/角色与操作资格 |
| /manager/agents、/manager/teams | 私有轻量配置、系统管理配置、所选视图；orchestrator 只能团队入口 |
| /manager/tasks | 创建原生任务/固定团，默认/覆盖/USE/视图校验；不另建 task 引擎 |
| /manager/skills、/manager/connectors | 原生库/连接能力 + 完整包、个人安装、技能广场标志与归属规则 |
| /manager/share-requests | 普通用户提交/查询自己的共享申请，不是授权管理页 |
| /manager/admin/users、/groups | admin 管理全部用户、组、role_type |
| /manager/admin/grants、/share-reviews | admin 授权、批准/拒绝共享；默认 all_users |
| /manager/admin/packages | admin 注册/加载/停用包及就绪状态 |
| 原生 /chat/、/sessions/... | 继续用原生聊天/停止/确认/历史/SSE，先校验身份和 SessionBinding |

原生 Agent 写入口、Session 任意模型/cwd/权限覆盖、Workspace Skill/MCP 写入口不能绕过企业规则。manager_router 关闭不意味着原生写接口已保护。PG get_session 忽略 agent_id 参数，入口必须显式匹配记录。

## 5. 首批必须验证的接入

1. 会话锁入口建立 ExecutionContext，早于原生读 Agent/Session/Workspace；Storage/工厂/后台/确认恢复读同一快照。
2. 同一 Agent 在不同会话的 private/shared/system 视图不串；源私有修改不泄露到对外共享。
3. 完整快照可随原生 State 往返 PG，不序列化客户端或工厂。
4. 静态 Team 使用 Record/Storage 先建完整关系，orchestrator 投影属于运行用户；不直接调用会提前唤醒的 AgentInvite 作为登记。
5. Skill/Tool 延迟取得保持原生 schema、权限、状态注入和完整文件；Middleware 在构造前注入。
6. 原生写接口和 admin API 封口；共享批准/授权同事务且幂等，无半成品权限。

这些是技术验证，不是已完成结果。失败先修订方案，不改 service、monkey patch、重写循环或重启 App 兜底。

## 6. Demo 与前端

Demo 至少包含系统 expert、用户轻量 expert、固定 Team（独立 orchestrator）、一个有可核验结果的 Tool、一份带附属文件的 Skill、本地 MCP。流程：启动 → 注册 1.0 无授权被拒绝 → admin 授权 → 运行 → 热加载 1.1 → 在用保持旧快照；另验证私有保存自用 → 申请共享 → 拒绝/通过 → 私有修改不影响旧共享。

前端固定放 egis-agentkit-frontend，左右布局、独立组件。普通用户：新任务、专家/专家团、技能/连接器、我的资源、共享申请状态、三个个人偏好文档。admin 额外显示用户/组、授权、共享审核、包状态。知识库暂不做，完整组件见 [页面规划](../../egis-agentkit-frontend/docs/V1页面与组件.md)。

ReMe 运行接入复用原生 middleware；完整记忆管理 CRUD 页面、记忆同步数据库需另评审，不与简单接入混算成已经完成。

## 7. 编码顺序

| 阶段 | 输出 | 验收 |
| --- | --- | --- |
| D0 当前 | 三个主设计、表/DTO/流程一致 | 先评审，不建表 |
| M0 | 上述公开接口组合的最小契约验证 | 原生源码零改动，钉版/视图/静态团/权限成立 |
| M1 | User/Group、当前 Definition、USE、共享审核与迁移 | 默认拒绝、自用无审、共享有审、来源撤销和幂等 |
| M2 | 发布物/热加载/按需资源、App 原生接口接入、业务 Demo | 不重启，失败不污染旧版，原生消息/状态真实可用 |
| M3 | 前端任务/资源/自用/共享申请与 admin 页面 | 全部接真实后端，前端字段/菜单权限与后端一致 |
| M4 | 联调与说明 | 真实模型、SSE/历史/确认/停止、用户目录/记忆隔离、失败场景 |

首版不做 MQ/集群、自研沙箱、整轮跨进程 Agent Worker、动态团队、配置回退、任意角色/组管理员、知识库/语音/渠道/定时任务 UI。工具级依赖可借 MCP 隔离；不能把它当成任意 middleware 冲突的自动解决方案。

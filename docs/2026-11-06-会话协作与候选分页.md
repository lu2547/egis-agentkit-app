# 当前会话协作与输入候选分页

## 页面行为

- `@`：上下文 / 专家；`/`：技能 / 命令。每次请求 10 条，滚动或键盘到边界时继续加载。
- 打开选择器、切换标签时焦点进入搜索框；上下方向键选择时列表同步滚动，保留深浅主题的中性灰样式。
- 个人助理保持主会话身份；选择专家后在输入框显示协作标签。发送后邀请进入当前会话协作，不创建另一个左侧任务。
- 发送被拒绝时保留输入、附件和邀请编号；刷新恢复已暂存的邀请，未开始的邀请可以移除。切换会话不会把迟到响应发送到新会话。
- 命令尚无真实注册来源，显示“暂无可用命令”；不将普通工具包装成命令。

## 接口与边界

`GET /manager/composer/options` 接收 category、query、cursor、limit、session_id / project_id，返回 items、next_cursor。上下文限定当前项目，排除 `.work`；专家与技能校验当前使用权限和可用性。

`POST /manager/tasks/{sid}/collaborators` 接收 request_id、experts（definition_id、resource_view_type），仅保存已校验的请求与专家快照，返回 Task。真实用户消息进入原生 on_reply 后才调用原生 TeamCreate / AgentInvite / TeamSay。

当前入口只允许个人助理用户主会话。独立专家不能担任主理人，固定团不能自由扩员。成员隐藏会话共享项目文件，采用独立默认工具权限；邀请不授予 USE，不继承主理人的 bypass。删除主任务清理所属隐藏运行记录，项目文件仍归项目管理。

调用原生团队工具的适配集中在 framework 的 compatibility 目录，未修改 AgentScope service 源码。原生成员持久化、消息投递和 PG 邀请检查点有独立提交点，故障恢复按至少一次补发；不承诺跨存储 exactly-once。
